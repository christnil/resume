Global Connect/IP-Only builds and operates one of Sweden's largest and neutral fiber networks. Their business model is to empower digitization by owning, developing and offering the best infrastructure and low level services for the digital society.

The focus of the project was to develop both customer-facing and internal IT systems. Before the project started, different parts of the company worked mostly in their own defined processes and tools. The tools could be purchased systems, but Excel and email were mostly used to handle sales and deliveries. The aim was to document all core processes across the different parts of the company, set up integrations and build new systems to make the work faster, easier and less error-prone.

### System developer .NET

I started the project as a backend .NET developer working with business sales support. IP-Only had just merged with another company called DGC and had inherited some .NET systems for searching connectivity options for addresses and some tools used for deliveries in the network acquired from DGC. The main issues with this project were that these systems were in bad shape and lacked documentation. Quickly after starting the project I raised the issues and proposed building the new requirements in the IP-Only stack and developing a new module in the legacy system to benefit from everything done in the IP-Only tech stack. This finally led to so much of the functionality already being in the IP-Only stack that we decided to build the UI and missing logic there as well and deprecate the old system. The value gained from this was a more reliable system, and the entire IT development department had the competence needed to fix bugs and monitor the system instead of having a single person responsible for all of this as before.

### Full stack developer Java/AngularJS

As the project progressed, the role became more and more that of a Java/AngularJS full-stack developer, continuing to build a customer portal. The goal was to let enterprise customers log in themselves and search for network options for their locations. We built this new customer-facing feature on the search engine described in the previous role. It had an Angular frontend for managing addresses and products. We integrated this system with a new self-developed product catalogue and a back-office UI to manage all products. The integration gave customers a faster way to get quotes, often with automatic replies, when buying new products.

### Full stack developer Java/AngularJS

When the first version of the customer portal was released, I felt that I wanted to try something new, and the client agreed to move me from the sales support team to the operational support team. There I started working in a development team where much of the work depended on just one team member. I worked closely with the project manager to develop a working development process and implement most of the Scrum model. This new role had a few different goals: setting up a back-office application for reserving and finding different forms of network identifiers; providing data for a new ServiceNow integration; and setting up APIs to fetch data from ServiceNow APIs. The other prioritised goal was unifying the stack used to monitor the two recently merged networks. This meant merging data sources and setting up new services to handle both networks. What I take away from this role is the soft skills I developed: coaching new team members and introducing stakeholders to sprint demos.
